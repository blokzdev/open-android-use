### 🛠 Changes Overview
**Scope:** `apps/OpenAndroidUseCompanion/agent` — a pure classifier + a loop gate.

**Key Actions:**
- **`RiskClassifier.kt`** (pure, tested): irreversible/externally-visible verb set
  (send/pay/delete/post/transfer/…), word-boundaried, keyed on the resolved action label and
  the trigger tools (click / perform_secondary_action / press_key).
- **`AgentController` risk gate**: `riskGatePasses` confirms a high-risk **or** injection-flagged
  action with a one-tap `ConfirmationSheet` — **even under a per-app grant** — and is skipped when
  per-action confirmation is already on (the batch confirm covered it). Wired into both execution
  paths (the trusted fast-path and the normal non-sensitive path).
- **Injection→confirm coupling**: `executeTool` now records `lastPerceptionFlagged` (from the 6.5c-4
  heuristic) so the next action after an injection-flagged screen is confirmed.
- Tests: `RiskClassifierTest` (flags send/pay/delete/post; spares Back/Next/'Sender details';
  only trigger tools count).

### 🧠 Design Intent (Why)
This is the third structural gate: redaction (L0) and element-level secret handoff are never
grant-aware; the **screen-level** gate is; and now the **risk** gate is also never grant-aware. A
grant buys routine convenience inside a trusted app, but an irreversible/external action (or one on a
screen that smells like injection) still gets a human's one tap. Pure + tight so it doesn't nag on
ordinary navigation, and it layers cleanly under the existing confirm-actions toggle.
