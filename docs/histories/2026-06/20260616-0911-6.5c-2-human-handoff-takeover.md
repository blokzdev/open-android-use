### 🛠 Changes Overview
**Scope:** `apps/OpenAndroidUseCompanion` (Kotlin agent loop + overlay + strings).

**Key Actions:**
- **New `agent/HandoffSheet.kt`**: an accessibility-overlay takeover ("🔒 You take it
  from here") modeled on `ConfirmationSheet` — parks the loop thread on a latch, Continue
  resumes / Stop ends, 300s timeout = Stop, `cancel()` wired into `requestStop`.
- **Decision seam** (`ToolExecutor.sensitivityBlock` + `sensitivityKind`): the loop asks
  *before* executing whether an action tool is blocked on the current sensitive screen; the
  in-`callTool` refusal stays as a backstop for direct callers.
- **Agent loop** (`AgentController` TOOL_USE branch): on a block, log a note, park on
  `HandoffSheet`; Continue → non-error `handedOffResult` (tells the model the user entered
  it and to re-observe) and end the batch so the next turn re-snapshots; Stop → interrupt.
  Handoff turns are neutral for stuck detection.
- **Auth-aware copy** (`SensitiveScreenDetector.classify` → PASSWORD/PAYMENT/BOTH) +
  externalized strings; classify unit-tested.

**Deferred (own focused PR):** 6.5c-2b login **tap-to-fill** (agent focuses the credential
field so the OS/password-manager chip appears) — Play-policy-sensitive, kept out of this

### 🧠 Design Intent (Why)
6.5a/b ended at a dead-end text refusal. The industry pattern (Operator/Anthropic/Mariner)
is a **human takeover** for logins/payments. The seam moves the sensitivity decision up into
the loop (which owns pause/resume + the overlay pattern) while keeping the executor's refusal
as a backstop, so the on-device agent gets the takeover UX and any direct/external caller
still fails safe. The handoff result is deliberately **non-error** so the model doesn't retry
the gated action — it re-observes and continues. The secret is always the human's; the agent
never types it.
