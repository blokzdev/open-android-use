### 🧠 Design Intent (Why)
A Light/Dark/System control is a baseline expectation and is orthogonal to Material You (which
chooses the *palette source*, not light/dark), so the two coexist. Centralizing the dark decision
inside `OpenAndroidUseTheme` keeps every surface consistent from one setting; threading
`settings.themeMode` through each Activity (rather than a global singleton) matches the existing
`dynamicColor` pattern, and reusing the same recreate-on-resume guard means no flash and no new
state machinery. Segmented buttons read as a single clear choice.
