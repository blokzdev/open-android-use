### 🛠 Changes Overview
**Scope:** `apps/OpenAndroidUseCompanion/agent` — new trust building blocks + tests. No
loop/UI wiring yet (that is 3b), so this PR changes no runtime behavior.

**Key Actions:**
- **`TrustGrant.kt`** — `GrantScope{ONCE,SESSION,PERSISTENT}`, `TrustGrant`, `AuditEntry`,
  and pure `TrustPolicy` (DECAY_DAYS=30 disuse decay, `isActive/decayed/touch/daysUntilDecay`).
- **`TrustCodec.kt`** — pure org.json encode/decode for grants + audit, plus `capped` ring-buffer.
- **`TrustStore.kt`** — persistent grants only (`filesDir/trust/grants.json`, atomic temp+rename
  like SessionStore), with lazy **decay-prune on read**; ONCE/SESSION stay in memory (3b).
- **`TrustAuditLog.kt`** — capped (500) append-only audit (`filesDir/trust/audit.json`), text-only.
- **`SensitiveScreenDetector.targetsSecretField`** — pure element-level check (type_text→focused
  field; element-addressed tools→element_index) so a grant can never let the agent type a secret.
- **Tests:** `TrustPolicyTest`, `TrustCodecTest`, `SecretTargetingTest` (pure JVM) +
  `TrustStoreInstrumentedTest` (grant/revoke, decay-prune, audit cap on real filesDir).

### 🧠 Design Intent (Why)
Default-deny scoped trust is the contraindication to a blanket "always allow" (NIST 800-207 /
Android auto-reset). Splitting the model out as pure, heavily-tested building blocks de-risks the
larger 3b integration (UI + loop). Storage is split by scope on purpose: only PERSISTENT touches
disk and it decays when unused; ONCE/SESSION are runtime-only so trust never silently outlives a
task. `targetsSecretField` is the security-critical seam that keeps a granted app still handing off
real secret-field entry — tested hard so it can't regress.
