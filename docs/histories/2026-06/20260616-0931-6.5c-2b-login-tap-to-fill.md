### 🛠 Changes Overview
**Scope:** `apps/OpenAndroidUseCompanion` (Kotlin) — handoff flow + a focus helper.

**Key Actions:**
- **`ActionExecutor.focusFirstSecureField`**: finds the first `isPassword` editable node
  and requests input focus (`ACTION_FOCUS`, falling back to accessibility focus) so the
  platform surfaces the user's own autofill / password-manager chip. **Never reads the
  field's text.** Best-effort (false if no field / focus refused — manual entry still works).
- **`AgentController` handoff**: on a PASSWORD/BOTH screen, focus the credential field
  before showing the takeover overlay; the password copy becomes tap-to-fill ("I've opened
  it — tap your saved login to fill it, or type it in… I never see it").
- Docs: spec L1 row marks tap-to-fill **built (best-effort)**; BACKLOG records an optional
  opt-out toggle; `V149` added.

### 🧠 Design Intent (Why)
The OS-mediated path lets the agent *assist* login without the secret ever entering the
model loop: the agent only focuses the field; the secret flows password-manager→field,
brokered by the OS, when the user taps the chip. Research is honest that this equals plain
handoff in security (it's "handoff with a nicer tap") and sits in a tightening corner of Play
policy — so it is **best-effort, disclosed in the overlay copy, gated by the existing guard,
and never load-bearing** (manual entry always works). No dedicated toggle yet (backlog).
