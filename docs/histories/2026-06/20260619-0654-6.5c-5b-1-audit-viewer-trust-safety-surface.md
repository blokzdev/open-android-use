### 🧠 Design Intent (Why)
6.5c-3a/3b already *write* a text-only `TrustAuditLog`, but 3c deferred its viewer; this surfaces it
so the user can answer "what has the agent done?". The audit is text-only by construction (tool +
resolved `ActionSummary`, never a field value), so the viewer can't leak a secret. The status lines
make the always-on protections (guard, injection defense) legible in one place. Reuses the 6.5c-3c
`DangerControl`/refresh/label-resolution patterns wholesale — no new infrastructure.
